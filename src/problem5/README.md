# A Crude Server

A TypeScript and Express API for managing tasks, persisted in a local SQLite
database. SQLite needs no separate database service; the application creates
the database directory, table, and index on startup.

## Requirements and setup

Use Node.js **24.8 or newer** with npm. SQLite is provided by Node's built-in
`node:sqlite` module, so no native database dependency needs to be installed.
Some Node versions emit an experimental SQLite warning.

From the repository root:

```sh
cd src/problem5
npm install
npm run dev
```

For a compiled build:

```sh
npm run build
npm start
```

Run validation and integration tests:

```sh
npm run typecheck
npm test
```

After the first install, `npm ci` can install the exact dependency versions
recorded in `package-lock.json`.

## Configuration

| Environment variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `3000` | HTTP port, an integer from 1 to 65535 |
| `HOST` | `127.0.0.1` | Listening address; use `0.0.0.0` to accept remote connections |
| `DATABASE_PATH` | `./data/tasks.sqlite` | SQLite file, relative to the working directory or absolute |

Set environment variables in the shell before starting the application.
No `.env` loader is used. For example, in PowerShell:

```powershell
$env:PORT = '3001'
$env:DATABASE_PATH = './data/development.sqlite'
npm run dev
```

Keep `DATABASE_PATH` unchanged between runs to retain your data. `:memory:`
is supported for temporary databases, but does not persist across restarts.
SIGINT and SIGTERM stop the server and close the database.

## Resource

```json
{
  "id": 1,
  "title": "Implement the API",
  "description": "Complete the CRUD endpoints",
  "status": "pending",
  "createdAt": "2026-10-14T00:00:00.000Z",
  "updatedAt": "2026-10-14T00:00:00.000Z"
}
```

- `title`: required on creation; trimmed, 1 to 200 characters.
- `description`: optional string, at most 5000 characters; defaults to `""`.
- `status`: `pending`, `in_progress`, or `completed`; defaults to `pending`.
- `id`, `createdAt`, and `updatedAt`: generated by the server and not writable.

Write requests require `Content-Type: application/json`. Unknown fields,
invalid values, and empty update objects are rejected. Null does not clear a
field; use an empty string to clear the description. Bodies are limited to 32 KB.

## Endpoints

| Method | Path | Behavior | Success |
| --- | --- | --- | --- |
| POST | `/tasks` | Create a task | 201, resource and `Location` header |
| GET | `/tasks` | List and filter tasks | 200, paginated collection |
| GET | `/tasks/:id` | Get task details | 200, resource |
| PATCH | `/tasks/:id` | Update supplied fields; preserve omitted fields | 200, updated resource |
| DELETE | `/tasks/:id` | Delete a task | 204, empty body |

List query parameters can be combined:

| Parameter | Behavior |
| --- | --- |
| `status` | Exact match on a valid status |
| `q` | Literal substring search in title and description; at most 200 supplied characters, nonempty after trimming |
| `limit` | Page size, 1 to 100; default 20 |
| `offset` | Nonnegative safe integer; default 0 |

Search uses SQLite's `lower`, which folds ASCII letter case. Results are ordered
by descending ID. `total` counts all matching tasks before pagination. Unknown
query parameters and repeated parameters are rejected.

```json
{
  "data": [],
  "total": 0,
  "limit": 20,
  "offset": 0
}
```

Errors have a consistent JSON shape:

```json
{ "error": { "message": "Task not found" } }
```

Error statuses include 400 for invalid input or malformed JSON, 404 for a missing
task or route, 413 for an oversized body, 415 for unsupported content types or
encodings, and 500 for unexpected server errors. Internal error details are
logged on the server rather than sent to clients.

## Examples

The following examples use a POSIX shell. In PowerShell, use `curl.exe` for curl
or `Invoke-RestMethod` with a JSON body.

```sh
curl -i -X POST http://127.0.0.1:3000/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Implement the API","description":"CRUD endpoints"}'

curl 'http://127.0.0.1:3000/tasks?status=pending&q=API&limit=10&offset=0'

curl http://127.0.0.1:3000/tasks/1

curl -X PATCH http://127.0.0.1:3000/tasks/1 \
  -H 'Content-Type: application/json' \
  -d '{"status":"completed"}'

curl -i -X DELETE http://127.0.0.1:3000/tasks/1
```

PowerShell creation example:

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:3000/tasks -Method Post `
  -ContentType 'application/json' -Body '{"title":"Implement the API"}'
```

## Design and scope

SQL values use bound parameters. Update column names come from a fixed field
allowlist. SQLite constraints also enforce the resource shape. Tests exercise
CRUD, combined filters, pagination, validation, malformed and oversized bodies,
missing resources, and persistence after reopening the database.

This challenge implementation has no authentication: callers can access all
tasks. Synchronous SQLite operations keep the implementation small but block
the event loop during queries, making this appropriate for a small service.
Schema creation is automatic; schema migrations are not included.

References: [Express error handling](https://expressjs.com/en/5x/guide/error-handling/)
and [Node SQLite documentation](https://nodejs.org/download/release/v24.8.0/docs/api/sqlite.html).
